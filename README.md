## О чём этот репозиторий

Шесть лабораторных — одна сквозная работа: от требований к модели и коду. Предметная область одна
на все лабораторные, поэтому модели должны быть согласованы между собой: прецеденты лаб. 1 →
классы предметной области лаб. 2 → системные последовательности лаб. 3 → диаграммы коммуникаций
лаб. 4 → классы проектирования лаб. 5 → код лаб. 6.

**Предметная область:** информационная подсистема **«Действия после получения патента»** —
сопровождение иностранного гражданина, получившего патент: контроль срока трудоустройства
(2 месяца с даты выдачи патента), заключение трудового договора или договора ГПХ, уведомление МВД
об осуществлении трудовой деятельности, учёт авансовых платежей НДФЛ и сроков действия патента.

**Границы.** Темы распределены по командам, поэтому модели строятся **только по разделу 7**
дорожной карты. Разделы 1–6 (миграционный учёт, дактилоскопия, медосвидетельствование, выбор
порядка трудоустройства, документы для патента, подача и получение патента) считаются
**предусловиями** и в модели входят только как вход; разделы 8–11 (программа переселения,
господдержка, РВП, ВНЖ) — темы других команд и в работу не входят.

Исходные материалы курса (лежат рядом, вне репозитория): `Лабораторные [7oNxcf].pptx`,
`1. Описание прецедентов.pptx`, `Дорожная карта [kmURdL].docx`.

## Распределение работы в команде

Тема одна на троих, поэтому лабораторные делятся по этапам сквозной работы:

| Участник | Лабораторные | Что делает | Статус |
|---|---|---|---|
| **Малышева Елена** | **1–2** | прецеденты (диаграмма + 7 спецификаций), модель предметной области (диаграмма классов + инварианты + глоссарий) | ✅ сделано, может служить образцом |
| **Макеев Глеб** | **3–4** | системные диаграммы последовательностей + спецификации операций, затем диаграммы коммуникаций по каждой системной функции | ⬜ не начато |
| **Мальгин Олег** | **5–6** | классы проектирования (согласованные с коммуникациями) + реализация ПО в git | ⬜ не начато |

**Почему так.** Лабораторные 1–2 задают словарь (имена прецедентов, акторов и сущностей), по
которому делаются все остальные: лаб. 3–4 разворачивают прецеденты в сообщения между объектами,
лаб. 5–6 превращают модель в код. Поэтому этап 1–2 — образец для двух других: имена прецедентов
(П01–П07), акторов (A1–A8) и сущностей из лаб. 2 не переименовываются.

**Правила согласованности между участниками:**

1. Имена прецедентов, акторов и сущностей берутся только из лаб. 1–2. Если что-то нужно менять —
   правится и лаб. 1–2, и всё, что от них зависит.
2. Каждая лабораторная — своя папка со своим `README.md` с разделом «открытые вопросы».
3. Ссылки между лабораторными оформляются относительными путями (например, из лаб. 3 на
   `lab1-usecases/usecases/03-uvedomlenie-mvd.md`), чтобы прослеживалась связь моделей.
4. Лабораторная считается готовой, когда выполнены все пункты её чек-листа в конце `README.md`.

## Как сдавать

1. **Один git-репозиторий на весь курс.** Каждая лабораторная — отдельная папка (`lab1-…`,
   `lab2-…`), внутри — отчёт `README.md` и исходники моделей (`.puml`, `.md`, при необходимости `.png`).
2. **Ветки не нужны.** В требованиях сказано: «требований к веткам не предъявляется». Работа
   ведётся в `main`, история — по коммитам «лаб. N: …». Это упрощает проверку: преподаватель
   видит линейную историю и итоговое состояние.
3. **Модели — текстом.** PlantUML и Mermaid вместо картинок: диффы читаемы, картинки
   пересобираются одной командой, не нужно коммитить бинарники (кроме финального PNG для отчёта).
4. **Согласованность между лабораторными** — см. правила выше.
5. **Сдача:** ссылка на репозиторий + папка лабораторной. По каждой работе — короткий отчёт
   в `README.md` (что сделано, какие решения, что осталось).
6. **Лаб. 6 — в этом же репозитории**, в `lab6-implementation/`: код, тесты, инструкция запуска.
