# П07. Формирование реестра и отчёта по патентам и договорам

| Поле | Значение |
|---|---|
| **Название** | Формирование сводного реестра (отчёта) по патентам, договорам и уведомлениям |
| **Рамки** | Подсистема «Действия после получения патента» |
| **Уровень** | Вспомогательная функция (служебный прецедент) |
| **Основной исполнитель** | Администратор системы (A8) |
| **Участники** | Администратор системы (A8); сотрудник ОВМ МВД (A3, закулисный интерес); ФНС (A6, закулисный интерес) |
| **Связанные прецеденты** | Расширяет П01; использует данные П02–П06 |
| **Статус** | **Расширение, требует подтверждения преподавателем** — в дорожной карте не описано, добавлено как служебная функция контроля |

## Заинтересованные лица и их интересы

| Лицо | Интерес |
|---|---|
| Администратор системы | Видеть сводную картину: у кого истекает срок, где есть просрочки и неуплаты |
| Руководитель организации (закулисный интерес) | Понимать объём и состояние работы с патентами |
| Сотрудник ОВМ МВД (закулисный интерес) | Наличие полных сведений о привлечении ИГ по патентам |
| Иностранный гражданин | Отчётность не должна раскрывать лишние персональные данные |

## Предусловия

- В подсистеме накоплены данные: учтённые патенты (П01), договоры (П02), уведомления (П03),
  платежи (П05), события прекращения (П06).
- У администратора есть права на формирование отчётов и выгрузку данных.
- Заданы параметры отчёта: период, регион, статус патента, наличие просрочек.

## Постусловия

- Сформирован отчёт (реестр) с колонками: ИГ (обезличенно или по реквизитам — в зависимости
  от прав), реквизиты патента, работодатель, дата договора, дата уведомления, статус оплаты,
  статус срока.
- Отчёт доступен для просмотра в системе и выгрузки в файл (CSV/PDF).
- Зафиксирован факт формирования: кто, когда, с какими параметрами.
- Персональные данные выданы в объёме, соответствующем правам администратора.

## Основной успешный сценарий

| № | Действия исполнителя | Отклик системы |
|---|---|---|
| 1 | Администратор открывает раздел «Отчёты» и выбирает вид отчёта | Система показывает доступные виды и права администратора |
| 2 | Администратор задаёт параметры: период, регион, статус патента, тип просрочек | Система проверяет корректность параметров и оценивает объём выборки |
| 3 | | Система собирает данные из карточек патентов, договоров, уведомлений и платежей |
| 4 | | Система формирует таблицу и подсвечивает критические записи (просрочки, неуплаты) |
| 5 | Администратор просматривает отчёт и при необходимости уточняет параметры | Система пересчитывает отчёт по новым параметрам |
| 6 | Администратор выгружает отчёт в файл | Система формирует файл (CSV/PDF), обезличивая данные при необходимости |
| 7 | | Система фиксирует факт выгрузки в журнале аудита |

## Альтернативные сценарии

**2а. По заданным параметрам данных нет.**
1. Система сообщает об отсутствии записей и предлагает расширить период или изменить фильтры.
2. Пустой отчёт не формируется.

**2б. Объём выборки слишком велик для выгрузки.**
1. Система предупреждает о размере и предлагает сузить период или регион.
2. Формируется агрегированный отчёт (сводка) вместо полного списка.

**6а. У администратора нет прав на выгрузку персональных данных.**
1. Система формирует отчёт в обезличенном виде (идентификатор вместо ФИО, маскированные реквизиты).
2. Попытка выгрузить полные данные фиксируется как отказ в журнале аудита.

**\*а. Обнаружена просрочка по сроку или неуплата.**
1. Система включает запись в блок «критические» и предлагает перейти к задаче исполнителя
   (П02, П03 или П05).
2. Факт просрочки сохраняется в отчёте с датой обнаружения.

**\*б. Данные обновлены во время формирования отчёта.**
1. Система фиксирует «срез данных» на момент запуска отчёта.
2. Изменения после среза отражаются только в следующем отчёте.

## Специальные требования

- Отчёт не должен раскрывать персональные данные сверх прав администратора; выгрузка — только
  для служебного использования.
- Отчёт формируется в «срезе»: состав данных фиксируется на момент запуска, а не «плавает»
  во время построения.
- Критические записи (просрочки, неуплаты) должны быть видны сразу, без дополнительной фильтрации.
- Все действия по формированию и выгрузке отчётов протоколируются (аудит).

## Частота использования

Периодически (например, ежемесячно) и по запросу; по срокам — не чаще, чем требуется для контроля.

## Открытые вопросы

- Является ли администратор системы отдельным актором или это тот же пользователь с расширенными
  правами (в лаб. 2 — отдельная сущность «Администратор»)?
- Нужен ли экспорт отчёта во внешние системы (МВД, ФНС) или только внутреннее использование?
- Требуется ли отчёт по каждому ИГ или достаточно агрегированных показателей?
- Относится ли отчётность к предметной области темы 7 или это функция всей системы сопровождения?
