## 1. Соглашения

| Что | Как договорились |
|---|---|
| **Имена операций** | русский camelCase, глагол в неопределённой форме + существительное: `зарегистрироватьПатент`, `направитьУведомлениеМВД`. Так имена согласованы с именами классов предметной области лаб. 2 (`Патент`, `УведомлениеМВД`), которые тоже русские. |
| **Сигнатура** | `имя(параметр: Тип, …, необязательный?: Тип) : Результат`. Необязательность помечается `?`. |
| **Уровень** | Операция — это то, что актор вызывает у подсистемы (системная операция). Всё, что происходит внутри, операцией не считается: внутренние обращения показаны только в лаб. 4. |
| **Одна операция — одна диаграмма коммуникаций** | По заданию лаб. 4 диаграмма строится «для каждой системной функции всех диаграмм последовательностей». Соответствие: операция → файл в [`../lab4-communication-diagrams/diagrams/`](../lab4-communication-diagrams/diagrams/). |
| **Предусловие / постусловие** | Предусловие проверяется при вызове; нарушение — это ошибка состояния, а не альтернативный сценарий. Постусловие формулируется для успешного завершения и отдельно — для отказа. |
| **Инварианты** | Ссылки на ИНВ-1…ИНВ-9 из [README лаб. 2](../lab2-domain-model/README.md#4-инварианты-предметной-области). Инвариант — то, что операция обязана сохранить или восстановить. |
| **Идемпотентность** | Повторный вызов операции при уже достигнутом результате должен возвращать тот же результат без дублирования данных (важно для приёма платежей, уведомлений и напоминаний). |

## 3. Контракты операций

### Операция 1. `зарегистрироватьПатент`

| | |
|---|---|
| **Назначение** | Учесть выданный патент: проверить реквизиты, рассчитать сроки от даты выдачи, создать карточку патента и комплект контрольных точек |
| **Прецедент** | [П01](../lab1-usecases/usecases/01-uchet-vydannogo-patenta.md) (основной сценарий, альтернативы 1а, 2а, 5а) |
| **SSD** | [01](diagrams/01-p01-osnovnoy.md), [02](diagrams/02-p01-alternativa-dubl.md), [03](diagrams/03-p01-alternativa-oshibki-rekvizitov.md), [12](diagrams/12-p04-alternativa-zaderzhka-vvoda.md) |
| **Диаграмма коммуникаций** | [01](../lab4-communication-diagrams/diagrams/01-zaregistrirovat-patent.md) |
| **Инициатор** | Иностранный гражданин (A1); при продлении — он же |
| **Частота** | однократно на каждый патент и при каждом продлении (переоформлении) |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `данныеПатента` | `ДанныеПатента` | да | серия, номер, дата выдачи, срок действия, регион выдачи, профессия (вид деятельности), орган, выдавший патент |
| `сканПатента` | `Вложение` | нет | файл скана или фотографии патента (вложение типа «патент») |
| `идПредыдущегоПатента` | `UUID` | нет | ссылка на прежний патент при продлении — новая карточка связывается с предыдущей |

**Результат:** `РезультатРегистрацииПатента{идПатента, статус, датаТрудоустройстваНеПозднее,
срокДействия, контрольныеТочки[2..*], дальнейшиеШаги[]}`; при ошибках валидации — `ОшибкиВалидации[]`
и `ЧерновикПатента`.

**Предусловия**

1. Патент получен в подразделении по вопросам миграции МВД (раздел 6.3 дорожной карты) — это вход подсистемы.
2. ИГ зарегистрирован; профиль, документ, удостоверяющий личность, и ИНН заполнены.
3. Справочники `Регион` и `ВидДеятельности` актуальны (не старше установленного срока).

**Постусловия (успех)**

1. Создан объект `Патент` со статусом «действует», связанный с ИГ, регионом и видом деятельности.
2. Рассчитана и сохранена дата `датаТрудоустройстваНеПозднее` = `датаВыдачи` + 2 месяца (календарные месяцы).
3. Создано не менее двух контрольных точек (ИНВ-9): «заключить договор», «направить уведомление»;
   обычно плюс «уплатить НДФЛ» и «продлить патент».
4. Вложение `сканПатента` сохранено и связано с патентем (при наличии).
5. Напоминания по созданным точкам запланированы (передача в операцию 8).

**Постусловия (отказ)**

1. При ошибках валидации (`Регион` не найден, `ВидДеятельности` недопустим, `датаВыдачи` в будущем)
   карточка не создаётся, возвращается `ЧерновикПатента` — данные не теряются.
2. При наличии другого действующего патента карточка не создаётся до вызова операции 2
   (или до отказа ИГ от регистрации).

**Инварианты:** ИНВ-4 (профессия из допустимого перечня), ИНВ-6 (не более одного действующего
патента), ИНВ-9 (точки не существуют без патента).

### Операция 2. `пометитьПатентАрхивным`

| | |
|---|---|
| **Назначение** | Перевести ранее учтённый патент в архивный статус, сохранив историю: закрыть его контрольные точки и прекратить напоминания |
| **Прецедент** | [П01](../lab1-usecases/usecases/01-uchet-vydannogo-patenta.md) (альтернативы 1а и *б) |
| **SSD** | [02](diagrams/02-p01-alternativa-dubl.md) |
| **Диаграмма коммуникаций** | [02](../lab4-communication-diagrams/diagrams/02-pometit-patent-arhivnym.md) |
| **Инициатор** | ИГ (подтверждает утрату силы патента); при аннулировании решением МВД — сотрудник ОВМ МВД (A3) |
| **Частота** | редко: при выдаче нового патента, аннулировании или истечении срока |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идПатента` | `UUID` | да | прежний патент |
| `основание` | `String` | да | «аннулирован» / «истёк» / «выдан новый» / решение МВД |

**Результат:** `Патент` со статусом «архивный», основанием и датой изменения.

**Предусловия**

1. Патент существует и имеет статус «действует» (или «оплачен_до»).
2. Указано основание утраты силы патента.

**Постусловия (успех)**

1. Атрибут `статус` патента — «архивный»; записаны основание и дата изменения.
2. Все открытые контрольные точки закрыты (статус «отменена») с указанием основания.
3. Напоминания по этим точкам прекращены.
4. Вложения (скан патента) сохранены — данные не удаляются.
5. Инвариант ИНВ-6 восстановлен: у ИГ не остаётся более одного действующего патента.

**Постусловия (отказ)**

1. Патент не найден или уже архивен — операция возвращает ошибку состояния, состояние не изменяется.
2. Отмена операции ИГ (ветвь «отменяю регистрацию») не является отказом: состояние подсистемы не изменяется.

**Инварианты:** ИНВ-6, ИНВ-9.

### Операция 3. `получитьСведенияОпатенте`

| | |
|---|---|
| **Назначение** | Выдать работодателю сведения о патенте кандидата (статус, срок, регион, профессии, оплачен до) для проверки права на работу |
| **Прецедент** | [П02](../lab1-usecases/usecases/02-trudovoy-dogovor.md) (шаг 2), [П06](../lab1-usecases/usecases/06-prekrashchenie-dogovora.md) |
| **SSD** | [04](diagrams/04-p02-osnovnoy.md), [05](diagrams/05-p02-alternativa-otkaz-rabotodatelya.md), [06](diagrams/06-p02-alternativa-prosrochka-sroka.md) |
| **Диаграмма коммуникаций** | [03](../lab4-communication-diagrams/diagrams/03-poluchit-svedeniya-o-patente.md) |
| **Инициатор** | Работодатель / заказчик по ГПХ (A2) |
| **Частота** | при каждой проверке кандидата |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `серия`, `номер` | `String` | да | реквизиты патента, сообщённые кандидатом |

**Результат:** `СведенияОпатенте{статус, срокДействия, оплаченДо, регион, видДеятельности[],
остатокСрокаТрудоустройства, признакПросрочки}`; либо «патент не найден».

**Предусловия**

1. Патент учтён (операция 1).
2. Пользователь имеет роль представителя работодателя (учётная запись активна).

**Постусловия**

1. Ни одна учётная сущность не изменена (операция только на чтение).
2. Возвращены сведения о патенте в объёме, необходимом работодателю.
3. **Не возвращаются:** персональные данные ИГ сверх необходимого и суммы платежей по НДФЛ —
   только факт `оплаченДо` (ограничение из специальных требований П05).

**Инварианты:** ИНВ-4 (профессии берутся из перечня патента), ИНВ-6 (проверяется наличие
действующего патента).

### Операция 4. `заключитьДоговор`

| | |
|---|---|
| **Назначение** | Зарегистрировать трудовой договор или договор ГПХ по патенту: проверить профессию, срок и отсутствие другого действующего договора; сохранить подписанный файл; создать задачу уведомления МВД |
| **Прецедент** | [П02](../lab1-usecases/usecases/02-trudovoy-dogovor.md) (основной сценарий, альтернативы 2а, 4а, 4б, 5а, *б), [П06](../lab1-usecases/usecases/06-prekrashchenie-dogovora.md) |
| **SSD** | [04](diagrams/04-p02-osnovnoy.md), [05](diagrams/05-p02-alternativa-otkaz-rabotodatelya.md), [06](diagrams/06-p02-alternativa-prosrochka-sroka.md), [16](diagrams/16-p06-osnovnoy.md) |
| **Диаграмма коммуникаций** | [04](../lab4-communication-diagrams/diagrams/04-zaklyuchit-dogovor.md) |
| **Инициатор** | Иностранный гражданин (A1); в сценарии П06 новый договор регистрирует он же |
| **Частота** | при каждом трудоустройстве по патенту |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идПатента` | `UUID` | да | патент, по которому заключён договор |
| `данныеДоговора` | `ДанныеДоговора` | да | вид (`трудовой` / `ГПХ`), работодатель, дата заключения, срок, профессия (для ГПХ — предмет и срок работ) |
| `файлПодписанногоДоговора` | `Вложение` | да | подписанный документ (или файл с электронной подписью) |

**Результат:** `Договор{идДоговора, вид, датаЗаключения, статус, признакПросрочки}`; при нарушении
ИНВ-1 или ИНВ-4 — отказ с указанием причины.

**Предусловия**

1. Патент учтён (операция 1) и действует.
2. По патенту **нет** другого действующего договора (ИНВ-1).
3. Договор подписан обеими сторонами; есть файл договора.
4. Срок трудоустройства не истёк — **не блокирующее** условие: при просрочке операция выполняется,
   но с признаком просрочки (см. альтернативу 2а П02).

**Постусловия (успех)**

1. Создан объект `Договор` (подкласс по `вид`) со статусом «заключён», связанный с патентеm,
   работодателем и видом деятельности.
2. Вложение `файлПодписанногоДоговора` сохранено (кратность `1..*`).
3. Контрольная точка «заключить договор» закрыта; создана точка «направить уведомление» со сроком
   не позднее `датаВыдачи` + 2 месяца.
4. Создана задача уведомления МВД (операция 6) для `СервисаУведомлений`.
5. Работодатель уведомлён о регистрации договора и сроке уведомления.

**Постусловия (отказ)**

1. Профессия по договору не входит в перечень патента — регистрация заблокирована (ИНВ-4).
2. По патенту уже есть действующий договор — регистрация отклонена (ИНВ-1), сначала операция 14.
3. Согласие стороны не подтверждено — создаётся только `ЧерновикДоговора`.

**Инварианты:** ИНВ-1, ИНВ-3, ИНВ-4.

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идПлатежа` | `UUID` | да | платёж в статусе «не_найден» / «недостаточно» |

| `документ` | `Вложение` | да | подтверждение из банка или ФНС |

**Результат:** `ПлатёжНДФЛ{статус = «подтверждён», источникВвода = «вручную, по документу»}` и
`Патент{оплаченДо}`.

**Предусловия**

1. Платёж существует и не подтверждён.
2. ИГ предоставил документ, подтверждающий платёж.
3. Причина неподтверждения разобрана (ошибочное зачисление / задержка сверки / доплата внесена).

**Постусловия (успех)**

1. Статус платежа — «подтверждён», с обязательной отметкой о ручном вводе и источнике.
2. Документ-основание сохранён.
3. Обновлён `оплаченДо`; непрерывность оплаты восстановлена (ИНВ-5).
4. Точка «уплатить НДФЛ» закрыта; снят риск аннулирования патента за этот период.
5. Событие запротоколировано в журнале аудита (ручной ввод — зона повышенного риска).

**Постусловия (отказ)**

1. Документ не подтверждает платёж — статус остаётся «не_найден», период остаётся непокрытым.
2. Сумма меньше установленной — требуется доплата; до доплаты период не признаётся оплаченным (ИНВ-7).

**Инварианты:** ИНВ-5, ИНВ-7.

## 6. Решения, отклонённые варианты и открытые вопросы

### 6.1. Принятые решения

1. **Операции названы по-русски в camelCase.** Так они согласованы с именами классов лаб. 2
   (`Патент`, `УведомлениеМВД`) и не вводят второй словарь (латиницу) в русскоязычную модель.
2. **Разделены похожие операции.** `зарегистрироватьПатент` / `пометитьПатентАрхивным`,
   `заключитьДоговор` / `отменитьДоговор` / `прекратитьДоговор`, `зарегистрироватьПлатёжНДФЛ` /
   `подтвердитьПлатёж`, `сформироватьРеестр` / `выгрузитьРеестр`. Причина одна: у таких пар разные
   предусловия, разные права и разные последствия, а также разные события-источники (ручной ввод,
   внешнее подтверждение, смена статуса).
3. **Заимствование операций между прецедентами вместо дублирования.** П06 использует
   `направитьУведомлениеМВД` и `заключитьДоговор`; П01 использует `пересчитатьСрокиПатента` (П04).
   Это соответствует отношениям `include` из диаграммы прецедентов.
4. **Просрочка не блокирует регистрацию договора.** `заключитьДоговор` при истёкшем сроке выполняется
   и возвращает признак просрочки: система ведёт учёт фактических отношений, а факт нарушения
   фиксируется отдельно (`зафиксироватьНарушениеСрока`).
5. **Операции-запросы явно выделены** (`получитьСведенияОпатенте`). Они не меняют состояние, зато
   снимают с прецедентов обязанность «показать данные» и дают право доступа (П02, П06).
6. **Ручной ввод всегда помечается.** `подтвердитьПлатёж` обязательно записывает источник и признак
   ручного ввода: иначе ручное подтверждение выглядело бы как автоматическое.
7. **Сущность «Инцидент» не вводилась.** В лаб. 2 её нет; роль инцидента играет просроченная
   критическая контрольная точка, видимая администратору в реестре (П07).
8. **Отчёт «РеестрПатентов» — проекция, а не класс.** В модели лаб. 2 отчёта нет, и это осознанно:
   отчёт строится из учётных сущностей и не имеет собственного жизненного цикла.
9. **Продление патента — не отдельная операция.** По частоте использования П01 («повторно при каждом
   продлении») продление оформляется новой карточкой через `зарегистрироватьПатент` со ссылкой на
   предыдущий патент.
10. **Внутренний триггер показан самообращением системы** (SSD П04) и компонентом `ПланировщикЗадач`
    (диаграммы коммуникаций 9, 10, 13). Это компромисс: время как актор в лаб. 1 намеренно не выделено,
    но операции, запускаемые по расписанию, нужно было изобразить.

### 6.2. Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Одна операция `заключитьИлиИзменитьДоговор` на все случаи | Разные предусловия (черновик / действующий договор) и разные юридические последствия; «универсальная» операция скрыла бы проверку ИНВ-1 |
| Операция `отправитьУведомлениеЧерезЕПГУ` и `отправитьУведомлениеПочтой` | Специальное требование П03 — формирование из одного набора данных для обоих каналов; канал должен быть параметром, а не отдельной операцией |
| Операция `найтиРаботу` / сущность `Вакансия` | В модели лаб. 2 нет класса `Вакансия`; подсистема не ведёт вакансии, она контролирует срок и предупреждает ИГ |
| Отдельная операция `сохранитьЧерновикПатента` | Черновик — это результат отказа операции 1, а не самостоятельное действие с собственным результатом |
| Сущность `Инцидент` и операция `создатьИнцидент` | Потребовала бы изменения лаб. 2; достаточно просроченной критической точки |
| Операция-обёртка `выполнитьКонтрольСроков` для П04 целиком | Пересчёт сроков и фиксация нарушения имеют разные последствия (нормальное обновление против юридически значимого факта) — оставлены двумя операциями |

### 6.3. Открытые вопросы (к преподавателю)
