## 1. Соглашения

| Что | Как договорились |
|---|---|
| **Имена операций** | русский camelCase, глагол в неопределённой форме + существительное: `зарегистрироватьПатент`, `направитьУведомлениеМВД`. Так имена согласованы с именами классов предметной области лаб. 2 (`Патент`, `УведомлениеМВД`), которые тоже русские. |
| **Сигнатура** | `имя(параметр: Тип, …, необязательный?: Тип) : Результат`. Необязательность помечается `?`. |
| **Уровень** | Операция — это то, что актор вызывает у подсистемы (системная операция). Всё, что происходит внутри, операцией не считается: внутренние обращения показаны только в лаб. 4. |
| **Одна операция — одна диаграмма коммуникаций** | По заданию лаб. 4 диаграмма строится «для каждой системной функции всех диаграмм последовательностей». Эти диаграммы — предмет отдельной лабораторной. |
| **Предусловие / постусловие** | Предусловие проверяется при вызове; нарушение — это ошибка состояния, а не альтернативный сценарий. Постусловие формулируется для успешного завершения и отдельно — для отказа. |
| **Инварианты** | Ссылки на ИНВ-1…ИНВ-7 из раздела 5 DESIGN.md. Инвариант — то, что операция обязана сохранить или восстановить. |
| **Идемпотентность** | Повторный вызов операции при уже достигнутом результате должен возвращать тот же результат без дублирования данных (важно для уведомлений и напоминаний). |

## 3. Контракты операций

### Операция 1. `зарегистрироватьПатент`

| | |
|---|---|
| **Сигнатура** | `зарегистрироватьПатент(данныеПатента: ДанныеПатента, сканПатента?: Вложение, идПредыдущегоПатента?: Ссылка) : РезультатРегистрацииПатента` |
| **Назначение** | Учесть выданный патент: проверить реквизиты, рассчитать сроки от даты выдачи, создать карточку патента и комплект контрольных точек |
| **Прецедент** | [П01](../lab1-usecases/usecases/01-uchet-vydannogo-patenta.md) (основной сценарий, альтернативы 1а, 2а, 5а) |
| **SSD** | [01](diagrams/01-p01-osnovnoy.md), [02](diagrams/02-p01-alternativa-dubl.md) |
| **Инициатор** | Иностранный гражданин (A1); при продлении — он же |
| **Частота** | однократно на каждый патент и при каждом продлении (переоформлении) |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `данныеПатента` | `ДанныеПатента` | да | серия, номер, дата выдачи, срок действия, регион выдачи, профессия (вид деятельности), орган, выдавший патент |
| `сканПатента` | `Вложение` | нет | файл скана или фотографии патента (вложение типа «патент») |
| `идПредыдущегоПатента` | `Ссылка` | нет | ссылка на прежний патент при продлении — новая карточка связывается с предыдущей |

**Результат:** `РезультатРегистрацииПатента{идПатента, статус, датаТрудоустройстваНеПозднее,
срокДействия, контрольныеТочки[2..*], дальнейшиеШаги[]}`; при ошибках валидации — `ОшибкиВалидации[]`
и `ЧерновикПатента`.

**Предусловия**

1. Патент получен в подразделении по вопросам миграции МВД (раздел 6.3 дорожной карты) — это вход подсистемы.
2. ИГ зарегистрирован; профиль, документ, удостоверяющий личность, и ИНН заполнены.
3. Справочники `Регион` и `ВидДеятельности` актуальны (не старше установленного срока).

**Постусловия (успех)**

1. Создан объект `Патент` со статусом «действует», связанный с ИГ, регионом и видом деятельности.
2. Рассчитана и сохранена дата `датаТрудоустройстваНеПозднее` = `датаВыдачи` + 2 месяца (календарные месяцы).
3. Создано не менее двух контрольных точек (ИНВ-6): «заключить договор», «направить уведомление»;
   обычно плюс «истекает срок действия патента».
4. Вложение `сканПатента` сохранено и связано с патентом (при наличии).
5. Напоминания по созданным точкам запланированы (передача в операцию 8).

**Постусловия (отказ)**

1. При ошибках валидации (`Регион` не найден, `ВидДеятельности` недопустим, `датаВыдачи` в будущем)
   карточка не создаётся, возвращается `ЧерновикПатента` — данные не теряются.
2. При наличии другого действующего патента карточка не создаётся до вызова операции 2
   (или до отказа ИГ от регистрации).

**Инварианты:** ИНВ-3 (срок трудоустройства считается от даты выдачи), ИНВ-5 (не более одного
действующего патента), ИНВ-6 (точки не существуют без патента).

### Операция 2. `пометитьПатентАрхивным`

| | |
|---|---|
| **Сигнатура** | `пометитьПатентАрхивным(идПатента: Ссылка, основание: String) : Патент` |
| **Назначение** | Перевести ранее учтённый патент в архивный статус, сохранив историю: закрыть его контрольные точки и прекратить напоминания |
| **Прецедент** | [П01](../lab1-usecases/usecases/01-uchet-vydannogo-patenta.md) (альтернативы 1а и *б) |
| **SSD** | [02](diagrams/02-p01-alternativa-dubl.md) |
| **Инициатор** | ИГ (подтверждает утрату силы патента); при аннулировании решением МВД — сотрудник ОВМ МВД (A3) |
| **Частота** | редко: при выдаче нового патента, аннулировании или истечении срока |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идПатента` | `Ссылка` | да | прежний патент |
| `основание` | `String` | да | «аннулирован» / «истёк» / «выдан новый» / решение МВД |

**Результат:** `Патент` со статусом «архивный», основанием и датой изменения.

**Предусловия**

1. Патент существует и имеет статус «действует».
2. Указано основание утраты силы патента.

**Постусловия (успех)**

1. Атрибут `статус` патента — «архивный»; записаны основание и дата изменения.
2. Все открытые контрольные точки закрыты (статус «отменена») с указанием основания.
3. Напоминания по этим точкам прекращены.
4. Вложения (скан патента) сохранены — данные не удаляются.
5. Инвариант ИНВ-5 восстановлен: у ИГ не остаётся более одного действующего патента.

**Постусловия (отказ)**

1. Патент не найден или уже архивен — операция возвращает ошибку состояния, состояние не изменяется.
2. Отмена операции ИГ (ветвь «отменяю регистрацию») не является отказом: состояние подсистемы не изменяется.

**Инварианты:** ИНВ-5, ИНВ-6.

### Операция 3. `получитьСведенияОпатенте`

| | |
|---|---|
| **Сигнатура** | `получитьСведенияОпатенте(серия: String, номер: String) : СведенияОпатенте` |
| **Назначение** | Выдать работодателю сведения о патенте кандидата (статус, срок, регион, профессии, остаток срока) для проверки права на работу |
| **Прецедент** | [П02](../lab1-usecases/usecases/02-trudovoy-dogovor.md) (шаг 2) |
| **SSD** | [03](diagrams/03-p02-osnovnoy.md), [04](diagrams/04-p02-alternativa-otkaz.md) |
| **Инициатор** | Работодатель / заказчик по ГПХ (A2) |
| **Частота** | при каждой проверке кандидата |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `серия`, `номер` | `String` | да | реквизиты патента, сообщённые кандидатом |

**Результат:** `СведенияОпатенте{статус, срокДействия, регион, видДеятельности[],
остатокСрокаТрудоустройства, признакПросрочки}`; либо «патент не найден».

**Предусловия**

1. Патент учтён (операция 1).

**Постусловия**

1. Ни одна учётная сущность не изменена (операция только на чтение).
2. Возвращены сведения о патенте в объёме, необходимом работодателю.
3. **Не возвращаются:** персональные данные ИГ сверх необходимого.

**Инварианты:** ИНВ-4 (профессии берутся из перечня патента), ИНВ-5 (проверяется наличие
действующего патента).

### Операция 4. `заключитьДоговор`

| | |
|---|---|
| **Сигнатура** | `заключитьДоговор(идПатента: Ссылка, данныеДоговора: ДанныеДоговора, файлПодписанногоДоговора: Вложение) : Договор` |
| **Назначение** | Зарегистрировать трудовой договор или договор ГПХ по патенту: проверить профессию, срок и отсутствие другого действующего договора; сохранить подписанный файл; создать задачу уведомления МВД |
| **Прецедент** | [П02](../lab1-usecases/usecases/02-trudovoy-dogovor.md) (основной сценарий, альтернативы 2а, 4а, 4б, 5а, *а) |
| **SSD** | [03](diagrams/03-p02-osnovnoy.md), [04](diagrams/04-p02-alternativa-otkaz.md) |
| **Инициатор** | Иностранный гражданин (A1) |
| **Частота** | при каждом трудоустройстве по патенту |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идПатента` | `Ссылка` | да | патент, по которому заключён договор |
| `данныеДоговора` | `ДанныеДоговора` | да | вид (`трудовой` / `ГПХ`), работодатель, дата заключения, срок, профессия (для ГПХ — предмет и срок работ) |
| `файлПодписанногоДоговора` | `Вложение` | да | подписанный документ (или файл с электронной подписью) |

**Результат:** `Договор{идДоговора, вид, датаЗаключения, статус, признакПросрочки}`; при нарушении
ИНВ-1 или ИНВ-4 — отказ с указанием причины.

**Предусловия**

1. Патент учтён (операция 1) и действует.
2. По патенту **нет** другого действующего договора (ИНВ-1).
3. Договор подписан обеими сторонами; есть файл договора.
4. Срок трудоустройства не истёк — **не блокирующее** условие: при просрочке операция выполняется,
   но с признаком просрочки (альтернатива 2а П02).

**Постусловия (успех)**

1. Создан объект `Договор` (подкласс по `вид`) со статусом «заключён», связанный с патентом,
   работодателем и видом деятельности.
2. Вложение `файлПодписанногоДоговора` сохранено.
3. Контрольная точка «заключить договор» закрыта; создана точка «направить уведомление» со сроком
   не позднее `датаВыдачи` + 2 месяца.
4. Создана задача уведомления МВД (операция 6) для `СервисаУведомлений`.
5. Работодатель уведомлён о регистрации договора и сроке уведомления.

**Постусловия (отказ)**

1. Профессия по договору не входит в перечень патента — регистрация заблокирована (ИНВ-4).
2. По патенту уже есть действующий договор — регистрация отклонена (ИНВ-1).
3. Согласие стороны не подтверждено — создаётся только `ЧерновикДоговора`.

**Инварианты:** ИНВ-1, ИНВ-3, ИНВ-4.

### Операция 5. `отменитьДоговор`

| | |
|---|---|
| **Сигнатура** | `отменитьДоговор(идДоговора: Ссылка, причина: String) : Договор` |
| **Назначение** | Отменить регистрацию незаключённого (чернового) договора, сохранив неуспешную попытку в истории |
| **Прецедент** | [П02](../lab1-usecases/usecases/02-trudovoy-dogovor.md) (альтернатива *а) |
| **SSD** | [04](diagrams/04-p02-alternativa-otkaz.md) |
| **Инициатор** | Работодатель (A2) или ИГ (A1) |
| **Частота** | по событию (отказ от сделки, срыв подписания) |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идДоговора` | `Ссылка` | да | черновик договора |
| `причина` | `String` | да | причина отмены (для истории и разбора) |

**Результат:** `Договор` со статусом «черновик» и признаком отмены; уведомление обеим сторонам.

**Предусловия**

1. Договор существует и находится в статусе «черновик» (согласие сторон не подтверждено).
2. Для действующего договора эта операция не применяется.

**Постусловия (успех)**

1. Черновик отклонён; действующий договор не создан — ИНВ-1 не нарушен.
2. Неуспешная попытка сохранена в истории с указанием причины и инициатора.
3. Обе стороны уведомлены.
4. Контрольная точка «заключить договор» **остаётся открытой**: срок продолжает идти (это меняет
   операция 9, а не эта).

**Постусловия (отказ)**

1. Договор уже заключён — операция возвращает ошибку состояния; такая ситуация требует другого
   порядка действий, не отмены черновика.
2. Договор не найден — ошибка состояния, состояние не изменяется.

**Инварианты:** ИНВ-1.

### Операция 6. `направитьУведомлениеМВД`

| | |
|---|---|
| **Сигнатура** | `направитьУведомлениеМВД(идДоговора: Ссылка, канал: КаналУведомления, подтверждение?: ПодтверждениеОтправки, правкиФормы?: ПоляФормы) : ПроектУведомления \| УведомлениеМВД` |
| **Назначение** | Сформировать уведомление МВД об осуществлении трудовой деятельности из данных договора и патента, отправить его через ЕПГУ или почтой и сохранить доказательства отправки |
| **Прецедент** | [П03](../lab1-usecases/usecases/03-uvedomlenie-mvd.md) (основной сценарий, альтернативы 1а, 1б, 2а, 4а) |
| **SSD** | [05](diagrams/05-p03-osnovnoy.md), [06](diagrams/06-p03-alternativa-pochta.md) |
| **Инициатор** | Работодатель / заказчик по ГПХ (A2) — обязанность п. 7.2 |
| **Частота** | на каждый договор и при каждом новом трудоустройстве |

**Параметры**

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `идДоговора` | `Ссылка` | да | договор, по которому направляется уведомление |
| `канал` | `КаналУведомления` | да | `ЕПГУ` или `почта` |
| `подтверждение` | `ПодтверждениеОтправки` | да при отправке | `{подписьЭП, датаПодписи}` для ЕПГУ; `{датаОтправки, трекНомер, опись}` для почты |

остатокСрока, вложения}`; при отправке — `УведомлениеМВД{идУведомления, канал, номерКвитанции |
трекНомер, датаНаправления, статус}`.

**Предусловия**

1. Договор заключён и зарегистрирован (операция 4).
2. Патент учтён и действует.
3. Уведомление направляется **не ранее** даты заключения договора и **не позднее** `датаВыдачи`
   + 2 месяца (ИНВ-2). Просрочка не блокирует отправку, но фиксируется.
4. Для канала ЕПГУ есть подтверждённая учётная запись работодателя; для почты — реквизиты для отправки.

**Постусловия (успех)**

1. Создан объект `УведомлениеМВД` со статусом «направлено» и заполненными реквизитами канала.
2. Сохранены доказательства: номер и дата квитанции (ЕПГУ) либо трек-номер и опись вложения (почта).
3. Копия договора вложена в уведомление.
4. Контрольная точка «направить уведомление МВД» закрыта; статус договора — «уведомление направлено».
5. ИГ уведомлён об исполнении обязанности; запланированы напоминания об окончании договора
   и срока патента.
6. При новом трудоустройстве по тому же патенту создаётся новое уведомление (ИНВ-7).

**Постусловия (отказ)**

1. Ошибка канала или возврат письма — уведомление в статусе «ошибка», задача остаётся открытой
   (далее операция 7).
2. Срок уведомления истёк — уведомление всё равно направляется, точка переводится в статус
   «просрочена» (операция 10).

**Инварианты:** ИНВ-2, ИНВ-7.

## 6. Решения, отклонённые варианты и открытые вопросы

### 6.1. Принятые решения

1. **Операции названы по-русски в camelCase.** Так они согласованы с именами классов лаб. 2
   (`Патент`, `УведомлениеМВД`) и не вводят второй словарь (латиницу) в русскоязычную модель.
2. **Разделены похожие операции.** `зарегистрироватьПатент` / `пометитьПатентАрхивным`,
   `заключитьДоговор` / `отменитьДоговор`. Причина одна: у таких пар разные предусловия
   и разные последствия, а также разные события-источники (ручной ввод, смена статуса).
3. **Заимствование операций между прецедентами вместо дублирования.** П01 и П02 используют
   `пересчитатьСрокиПатента` (владелец операции — П04): при регистрации патента и заключении
   договора создаются и пересчитываются контрольные точки. Это соответствует отношениям `include`
   из диаграммы прецедентов.
4. **Просрочка не блокирует регистрацию договора.** `заключитьДоговор` при истёкшем сроке выполняется
   и возвращает признак просрочки: система ведёт учёт фактических отношений, а факт нарушения
   фиксируется отдельно (`зафиксироватьНарушениеСрока`).
5. **Операции-запросы явно выделены** (`получитьСведенияОпатенте`). Они не меняют состояние, зато
   снимают с прецедентов обязанность «показать данные».
6. **Сущность «Инцидент» не вводилась.** В лаб. 2 её нет; роль инцидента играет просроченная
   критическая контрольная точка.
7. **Продление патента — не отдельная операция.** По частоте использования П01 («повторно при каждом
   продлении») продление оформляется новой карточкой через `зарегистрироватьПатент` со ссылкой на
   предыдущий патент.
8. **Внутренний триггер показан самообращением системы** (SSD П04). Это компромисс: время как актор
   в лаб. 1 намеренно не выделено, но операции, запускаемые по расписанию, нужно было изобразить.

### 6.2. Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Одна операция `заключитьИлиИзменитьДоговор` на все случаи | Разные предусловия (черновик / действующий договор) и разные последствия; «универсальная» операция скрыла бы проверку ИНВ-1 |
| Операция `отправитьУведомлениеЧерезЕПГУ` и `отправитьУведомлениеПочтой` | Специальное требование П03 — формирование из одного набора данных для обоих каналов; канал должен быть параметром, а не отдельной операцией |
| Операция `найтиРаботу` / сущность `Вакансия` | В модели лаб. 2 нет класса `Вакансия`; подсистема не ведёт вакансии, она контролирует срок и предупреждает ИГ |
| Отдельная операция `сохранитьЧерновикПатента` | Черновик — это результат отказа операции 1, а не самостоятельное действие с собственным результатом |
| Сущность `Инцидент` и операция `создатьИнцидент` | Потребовала бы изменения лаб. 2; достаточно просроченной критической точки |
| Операция-обёртка `выполнитьКонтрольСроков` для П04 целиком | Пересчёт сроков и фиксация нарушения имеют разные последствия (нормальное обновление против юридически значимого факта) — оставлены двумя операциями |

### 6.3. Открытые вопросы (к преподавателю)

1. **Достаточно ли 10 операций?** Набор ровно соответствует четырём прецедентам и ориентиру задания;
   альтернативные сценарии не добавляют операций, а меняют предусловия и результаты.
2. **Нужен ли отдельный класс «Инцидент»** для просрочек? Сейчас его роль выполняет просроченная
   критическая контрольная точка.
3. **Кто является инициатором операций по расписанию** (`пересчитатьСрокиПатента`,
   `зафиксироватьНарушениеСрока`): оставить внутренний триггер (текущее решение) или ввести актора
   «Планировщик» / «Время»?
4. **«2 месяца» — календарные месяцы.** В модели принят календарный месяц (истекает в
   соответствующее число), как и в лаб. 1–2; документ этого не уточняет.
5. **Кто уведомляет МВД при договоре ГПХ** — работодатель или заказчик — не разграничено
   (открытый вопрос П03 из лаб. 1). В модели обязанность закреплена за A2.
6. **Нужна ли проверка принятия уведомления ведомством** (квитанция о вручении) или достаточно факта
   отправки. В модели контроль вручения есть только для почтового канала (по трек-номеру).
