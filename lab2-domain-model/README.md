# Лабораторная 2. Модель предметной области

**Дисциплина:** Функциональное моделирование систем
**Преподаватель:** Ткаченко И. Н., ТюмГУ
**Команда:** Малышева Елена, Макеев Глеб
**Тема:** 7. Действия после получения патента (пункты 7.1 и 7.2)

## Что моделируем

Предметная область — работа иностранного гражданина по патенту: патент, договор с работодателем,
уведомление МВД и сроки, которые за этим следят. Модель строится на основе прецедентов лабы 1:
П1 «Заполнить анкету» и П2 «Просмотреть дорожную карту».

## Классы (10)

| Класс | Атрибуты | Что означает |
|---|---|---|
| `ИностранныйГражданин` | фио, гражданство, документЛичности, телефон | владелец патента |
| `Патент` | серия, номер, датаВыдачи, срокДействия, регион, профессия, статус | право работать; от даты выдачи считаются сроки 7.1 и 7.2 |
| `Работодатель` | наименование, инн, тип | организация, ИП или заказчик по ГПХ |
| `Договор` *(abstract)* | номер, датаЗаключения, датаОкончания, статус | правовая форма трудовых отношений |
| `ТрудовойДоговор` | должность, режим | договор по трудовому кодексу |
| `ДоговорГПХ` | предмет, срокРабот | договор на работы или услуги |
| `УведомлениеМВД` | датаНаправления, канал, номерКвитанции, трекНомер, статус | исполнение п. 7.2 и доказательства отправки |
| `КонтрольнаяТочка` | вид, плановаяДата, фактическаяДата, статус | срок, который система показывает в карте |
| `Напоминание` | датаПоказа, статус | предупреждение о приближении срока |
| `Документ` | тип, имяФайла, датаЗагрузки | скан патента, файл договора, копия, квитанция |

Атрибуты указываются без идентификаторов, модификаторов доступа и методов: это этап анализа,
обязанности появятся в лабе 5.

## Связи и кратности

| Связь | Кратность | Смысл |
|---|---|---|
| ИностранныйГражданин → Патент | 1 → 0..* | патентов может быть несколько |
| Патент → Договор | 1 → 0..1 | на патент — не более одного действующего договора |
| Работодатель → Договор | 1 → 0..* | у договора ровно один работодатель |
| Договор → УведомлениеМВД | 1 → 0..1 | по договору — не более одного уведомления |
| Патент ◆→ КонтрольнаяТочка | 1 → 0..* | композиция: точек без патента не существует |
| КонтрольнаяТочка → Напоминание | 1 → 0..* | по одной точке может быть серия предупреждений |
| Патент ◇→ Документ | 1 → 0..* | агрегация: документ существует и отдельно |
| Договор ◇→ Документ | 1 → 0..* | файл договора |
| УведомлениеМВД ◇→ Документ | 1 → 0..* | копия договора и квитанция |

Ромб стоит у «целого»: закрашенный — композиция, пустой — агрегация.

## Инварианты

| ID | Инвариант |
|---|---|
| ИНВ-1 | На патент — не более одного действующего договора |
| ИНВ-2 | Договор заключается не позднее 2 месяцев с даты выдачи патента |
| ИНВ-3 | Уведомление направляется не ранее договора и не позднее 2 месяцев с даты выдачи патента |
| ИНВ-4 | Уведомление относится к действующему договору |
| ИНВ-5 | У одного гражданина не более одного действующего патента |
| ИНВ-6 | Контрольные точки не существуют без патента |

## Решения

1. **`Договор` — абстрактный класс.** В п. 7.1 две формы: трудовой договор и ГПХ. Общее (номер,
   даты, статус, связи) описано один раз, различия — в подклассах.
2. **`Документ` — один класс с атрибутом `тип`,** без иерархии: поведение одинаковое, различается
   только содержимое.
3. **Регион и профессия — атрибуты патента,** а не отдельные классы: для пунктов 7.1 и 7.2 нужен
   только факт «патент выдан в таком-то регионе по такой-то профессии».
4. **Справочников и администратора нет:** они не участвуют в прецедентах лабы 1.

- Классы проектирования и реализация — лабы 4–5 (в этом семестре не сдаём).
