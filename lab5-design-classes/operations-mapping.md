# Трассировка «системная операция → класс → метод» (лаб. 5)

**Дисциплина:** Функциональное моделирование систем · **ТюмГУ**, 5 семестр · **Преподаватель:** Ткаченко И. Н.

Этот файл раскрывает таблицу «операция → класс → метод» из [README](README.md) подробно: для каждой
из 16 системных операций лаб. 3 указаны контракт, класс-владелец, метод, классы-участники и
хранилища/шлюзы, к которым операция обращается.

**Как читать.** Класс-владелец — тот, что первым получает сообщение от актора (в лаб. 4 —
компонент-координатор). Классы-участники — те, чьи объекты создаются, изменяются или читаются.
Хранилища и шлюзы — единственные точки выхода из управляющего слоя. Обозначения стереотипов:
`B` — boundary, `C` — control, `E` — entity, `R` — repository, `G` — gateway.

## 2. Подробно по операциям

### 1. `зарегистрироватьПатент` → `СервисПатентов.зарегистрировать`

- **Контракт:** [операция 1](../lab3-sequence-diagrams/operations.md#операция-1-зарегистрироватьпатент).
- **Что делает метод:** проверяет реквизиты (`проверитьРеквизиты`), единственность действующего патента
  (`проверитьЕдинственность`, ИНВ-6), считает сроки через `МодульКонтроляСроков`, создаёт `Патент`,
  `КонтрольнаяТочка[2..*]` и `Документ` (скан), сохраняет агрегат.
- **Классы-участники:** `ЭкранПатента` (ввод), `ИностранныйГражданин` (владелец), `Патент`, `КонтрольнаяТочка`,
  `Документ`, `МодульКонтроляСроков`, `СервисНапоминаний` (планирование серии напоминаний).
- **Хранилища:** `РеестрПатентов` (запись агрегата), `СправочникРегионов` (проверка региона),
  `СправочникВидовДеятельности` (ИНВ-4), `ХранилищеДокументов` (скан).
- **Результат:** `Патент`; при отказе — `ОшибкиВалидации[0..*]` (проекция) и черновик данных.
- **Диаграмма:** [01](diagrams/01-layers.md), [02](diagrams/02-patent-dogovor.md).

### 2. `пометитьПатентАрхивным` → `СервисПатентов.пометитьАрхивным`

- **Контракт:** [операция 2](../lab3-sequence-diagrams/operations.md#операция-2-пометитьпатентархивным).
- **Что делает метод:** проверяет, что патент действует; вызывает `Патент.архивировать(причина)`, закрывает
  открытые точки через `МодульКонтроляСроков.закрытьТочку`, снимает напоминания.
- **Участники:** `ЭкранПатента`, `Патент`, `КонтрольнаяТочка`, `МодульКонтроляСроков`, `СервисНапоминаний`.
- **Хранилище:** `РеестрПатентов`. Документы не удаляются (ИНВ-8).
- **Диаграмма:** [02](diagrams/02-patent-dogovor.md).

### 3. `получитьСведенияОпатенте` → `СервисПатентов.выдатьСведения`

- **Контракт:** [операция 3](../lab3-sequence-diagrams/operations.md#операция-3-получитьсведенияопатенте).
- **Что делает метод:** операция только на чтение; собирает проекцию `СведенияОпатенте` (статус, срок,
  `оплаченДо`, регион, профессии, остаток срока трудоустройства).
- **Участники:** `ЭкранПатента`, `ПредставительРаботодателя` (запрашивающий), `Патент`,
  `МодульКонтроляСроков` (остаток срока), `СервисНДФЛ` (только `оплаченДо`, без сумм), `МодульПравДоступа`.
- **Хранилища:** `РеестрПатентов`, `СправочникВидовДеятельности`.
- **Ограничение:** суммы платежей НДФЛ в результат не входят (требование П05) — это видно по составу
  параметров методов и по отсутствию `ПлатёжНДФЛ` среди участников.
- **Диаграмма:** [02](diagrams/02-patent-dogovor.md).

### 4. `заключитьДоговор` → `СервисДоговоров.заключить`

- **Контракт:** [операция 4](../lab3-sequence-diagrams/operations.md#операция-4-заключитьдоговор).
- **Что делает метод:** проверяет отсутствие действующего договора (ИНВ-1), допустимость профессии
  (ИНВ-4), сравнивает дату заключения со сроком трудоустройства (ИНВ-3, не блокирующе), создаёт подкласс
  `Договор` по виду, прикладывает файл, закрывает точку «заключить договор» и создаёт задачу уведомления.
- **Участники:** `ЭкранДоговора`, `ИностранныйГражданин`, `Работодатель`, `Договор` / `ТрудовойДоговор` /
  `ДоговорГПХ`, `Патент`, `Документ`, `МодульКонтроляСроков`, `СервисУведомлений`.
- **Хранилища:** `РеестрДоговоров`, `РеестрПатентов`, `СправочникВидовДеятельности`, `ХранилищеДокументов`.
- **Диаграмма:** [02](diagrams/02-patent-dogovor.md).

### 5. `отменитьДоговор` → `СервисДоговоров.отменить`

- **Контракт:** [операция 5](../lab3-sequence-diagrams/operations.md#операция-5-отменитьдоговор).
- **Что делает метод:** переводит черновик в отклонённый, сохраняет причину и инициатора; контрольная
  точка «заключить договор» остаётся открытой (срок продолжает идти).
- **Участники:** `ЭкранДоговора`, `Договор`, `СервисНапоминаний`.
- **Хранилище:** `РеестрДоговоров`.
- **Диаграмма:** [02](diagrams/02-patent-dogovor.md).

### 6. `направитьУведомлениеМВД` → `СервисУведомлений.направить`

- **Контракт:** [операция 6](../lab3-sequence-diagrams/operations.md#операция-6-направитьуведомлениемвд).

- **Хранилища и шлюзы:** `РеестрУведомлений`, `РеестрДоговоров`, `ХранилищеДокументов`, `ШлюзЕПГУ`, `ШлюзПочты`.

### 7. `зафиксироватьВозвратУведомления` → `СервисУведомлений.зафиксироватьВозврат`

- **Контракт:** [операция 7](../lab3-sequence-diagrams/operations.md#операция-7-зафиксироватьвозвратуведомления).

  документ возврата; точка не закрывается.
- **Участники:** `ЭкранУведомленияМВД`, `УведомлениеМВД`, `Документ`, `КонтрольнаяТочка`,
  `МодульКонтроляСроков`, `СервисНапоминаний`.
- **Хранилища и шлюзы:** `РеестрУведомлений`, `ХранилищеДокументов`, `ШлюзПочты` (сведения о возврате).
- **Диаграмма:** [03](diagrams/03-uvedomleniya-kontrol.md).

### 8. `настроитьНапоминания` → `СервисНапоминаний.настроить`

- **Контракт:** [операция 8](../lab3-sequence-diagrams/operations.md#операция-8-настроитьнапоминания).
- **Что делает метод:** сохраняет каналы, моменты и согласие в профиле, создаёт `Напоминание` по каждой
  открытой точке и каждому моменту; по закрытым точкам напоминания не создаются (ИНВ-9).
- **Участники:** `ЭкранНапоминаний`, `ПользовательИГ`, `Напоминание`, `КонтрольнаяТочка`,
  `МодульКонтроляСроков`.
- **Хранилище:** `РеестрПатентов` — напоминания входят в агрегат патента (композиция), отдельного
  реестра напоминаний в модели нет.
- **Диаграмма:** [03](diagrams/03-uvedomleniya-kontrol.md).

## 4. Замена хранилищ по сравнению с лаб. 4

| Лаб. 4 | Лаб. 5 | Причина замены |
|---|---|---|
| `РеестрПатентов` (одно хранилище на всё) | `РеестрПатентов`, `РеестрДоговоров`, `РеестрУведомлений`, `РеестрПлатежей`, `ХранилищеДокументов` | в модели проектирования хранилище обслуживает один агрегат: иначе класс-хранилище превращается в «бог-объект» и тянет за собой все сущности |
| `СправочникРегионов`, `СправочникВидовДеятельности` | без изменений (`<<repository>>`) | справочники и остаются справочниками |
| `ШлюзЕПГУ`, `ШлюзПочты`, `ШлюзФНС` | без изменений (`<<gateway>>`) | граница с внешними системами не изменилась |

Контрольные точки и напоминания отдельного реестра не получили: они входят в агрегат `Патент`
(композиция `1 → 2..*` и `1 → 0..*`), поэтому сохраняются через `РеестрПатентов`.

## 5. Типы, которых нет среди классов модели

Проекции и служебные типы создаются на время операции и не хранятся, поэтому классами не являются
(в отличие от `ОтчётРеестр`, у которого есть собственный жизненный цикл):

| Тип | Где используется | Состав |
|---|---|---|
| `СведенияОпатенте` | операция 3 | статус, срок действия, `оплаченДо`, регион, профессии, остаток срока, признак просрочки |
| `РезультатРегистрацииПатента` | операция 1 | `идПатента`, статус, дата трудоустройства не позднее, контрольные точки, дальнейшие шаги |
| `СводкаСроков` | операция 9 | открытые, критические, просроченные точки |
| `ПроектУведомления` | операция 6 | поля формы, срок направления, вложения |
| `ФайлВыгрузки` | операция 16 | имя, формат, размер, хэш, признак обезличивания |
| `РасчётПлатежа`, `СостояниеРасчётов` | операции 11–13 | сумма к уплате, период, задолженность |
| `ОшибкиВалидации`, `НастройкиНапоминаний`, `СобытиеАудита`, `СтрокаРеестра` | 1, 8, 15–16 | вспомогательные структуры |
